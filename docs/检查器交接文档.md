# 严格对位规则检查器 —— 交接文档

> 这份文档是为了让**另一轮对话**接手完善检查器而写的。
> 它记录了：现在有什么、判据从哪来、怎么验证、还剩什么问题。
> 网站本体（`index.html`）不依赖这份文档，检查器出问题不影响看内容。

---

## 一、这是什么

`theory/counterpoint.js` —— 一个二声部严格对位的**规则检查器**，21 条规则。
它同时承担两个角色：

1. **练习自动批改**：学习单元里的「找错」练习不看你选什么答案，而是现场跑这个检查器，你的选项编号必须出现在检查器的报告里才算对。
2. **素材质量闸门**：`tools/verify.js` 在谱例进课程前先过一遍。

设计原则写在文件顶部：**每条规则都有编号、中英名称、判据说明、依据来源，可单独开关**。
因为不同教材在细节上并不一致（尤其反向五八度、连续三六度的上限），
所以规则做成可切换的，而不是硬编码。

## 三、判据从哪来 —— 以及一个必须说清的限制

`RULES` 表里每条规则都写了依据来源，指涉的教材是：

- Fux《Gradus ad Parnassum》—— 五种对位的经典框架
- Jeppesen《Counterpoint: The Polyphonic Vocal Style of the 16th Century》
- Salzer & Schachter《Counterpoint in Composition》
- 陈铭志《复调音乐写作基础教程》/ 于苏贤《复调音乐教程》

**但必须说清：这些教材的原文我拿不到**（PDF 抓取受支持限制）。
所以这 21 条规则是我按**通行教学共识**写的，不是逐字引用任何一本。

这正是为什么现在要做第四节的交叉验证 —— **不是靠"我引用了教材"，而是靠"权威范例认不认"。**

## 四、核心资产：用 Fux 原文检验检查器

### 语料来源

[`github.com/MarkGotham/species`](https://github.com/MarkGotham/species)

- Fux《Gradus ad Parnassum》**全部**对位练习：二声部 46 条、三声部 44 条、四声部 32 条
- **Fux 本人的解答**，不是后人重写的
- 编号用 Norton/Mann 1965 版图号
- 格式：`.krn`（纯文本，可程序解析）、`.mxl`、`.mscz`（MuseScore 可直接打开）
- **授权：渲染乐谱 CC0 公有领域**

仓库 README 还给出了 Fux 为每个调式规定的固定旋律音高序列，
`tools/validate-fux.js` 里的 `FUX_CF` 表就是从那里抄的，并已逐音核对。

### 验证逻辑

```
对每个 .krn 文件：
  ① 用 theory/kern.js 解析
  ② 认出哪个声部是固定旋律（全音符那个），并核对它与 Fux 规定的 CF 逐音吻合
     —— 允许整体八度移位、允许开头缺 1–2 个音（图 13、42 有这类例外）
  ③ 把 Fux 的解答喂给 CP.check()
  ④ 报出：语料核对结果 + 检查器判定
```

**这个方向是关键**：不是"我生成对位"，而是"**权威范例说了算**"。
如果 Fux 的解答被判违规，几乎一定是检查器错了。

### 已经抓出的 4 个真 bug

| # | 问题 | 性质 | 出处 |
|---|---|---|---|
| 1 | 不认识 **cambiata（换音）**——级进进入、同向跳三度、反向级进折回。第三类的标志音型 | 漏检一整个音型 | Fux 图 55 |
| 2 | `M02 大跳后未反向级进`太严：Fux 八度下行大跳后用三度折返 | 规则过严 | Fux 图 55 |
| 3 | **kern 休止符解析坏了**：正则写成 `/^r+$/`，但 kern 里是 `2r`，于是带时值的休止全被静默丢弃，导致小节时长错位 | 解析器 bug | Fux 图 73、82 |
| 4 | 第五类照搬了第三类"强拍必须协和"的判据，但**第五类允许挂留落在强拍、甚至跨小节** | 规则错 | Fux 图 82 |

处理方式：
- #1、#3、#4 直接修。
- #2 **没有继续放宽阈值**，而是把 `M02` 从 `error` 降级为 `warn`。
  理由：那是在为一个样本调参（过拟合），而"大跳须级进折返"本身是风格准则，
  连 Fux 都偏离，当硬规则会冤枉正确写法。**如果你认为该保留为硬规则，改 `RULES.M02.level` 即可。**

### 当前状态

```
node tools/validate-fux.js
→ 语料核对：5 个文件全部与 Fux 规定一致
→ 规则检查：Fux 的解答 5 条全部通过（0 错误）
```

覆盖：图 5（一类）、33（二类）、55（三类）、73（四类）、82（五类），调式终止音均为 d。

### 5.1 扩充语料（最重要）

**建议优先抓的图号**（覆盖五种对位 × 多种调式 × CF 在上下两个位置）：

| 类别 | 图号 |

**重点看 CF 在上方的那些**（图 6, 35, 37, …）—— 现在的检查器默认
「对位声部在下」，`localOk` 之类的假设可能只适用于 CF 在下方的布局。
这是最可能藏 bug 的地方。

### 5.2 需要判断的具体问题

1. **CF 在上方时检查器是否仍然正确？** 见上。
2. **第三类的"次强拍"（每小节第 3 拍）**：本站检查器**不区分**它，
   但部分教材对该拍的不协和限制更严。要不要加？加了会让多少 Fux 的写法变违规？
3. **`M02` 该是 error 还是 warn？** 见第四节。
4. **反向到达五度/八度（H04）** 现在是 `warn`。Fux 体系允许，部分中文教材规避。
   语料变多后可以统计 Fux 实际用了多少次，用数据决定。
5. **三声部与四声部**：检查器目前只做二声部。
   仓库里三声部（II）和四声部（III）的语料也在，但需要新增
   「声部对」「外声部」「内声部」的概念，以及平行五八度在三声部里的完整判据
   （任意两声部之间都要查）。这是一块独立的工作。
6. **调式 vs 大小调**：现在检查器不区分调式，`makeScore` 的 `key` 参数基本没用上。
   比如多利亚调式里的 B♭ 和 C♯（musica ficta）现在靠谱面显式写出来。
   要不要把调式规则（第六级、第七级的变化）内建进去？

### 5.3 应该保留的验证习惯

每改一次规则，跑这六条：


## 六、已知的坑与不要做的事

### 不要再用 `tools/generate.js` 去"生成"谱例

它当初的用途是"求解器产出对位、检查器当裁判"，但走不通：
- 第三类搜索空间 33 个槽位，穷举不出解（加了候选排序和剪枝后勉强能出，但质量差）
- 生成出来的解**规则合规但音乐上很呆**（大量同音反复）
- 根本问题是**方向错了**：这类素材 Fux 已经写好并且是公有领域，没有生成的必要

文件已经删掉了（原 README 里有记录）。它的剪枝逻辑对理解约束有用，
但**新谱例一律用 Fux 语料**。

### 检查器不保证的事

- **音乐性**：规则合规 ≠ 好听。生成器出的解就是反例。
- **风格归属**：16 世纪实际写法与 Fux 的教科书规范有出入（Jeppesen 的核心论点）。
  检查器实现的是教科书规范。
- **文字讲解的理论细节**：那部分需要人校对。

### 静默失败是最糟的失败

kern 休止符那个 bug 之所以难发现，是因为它**丢数据时不出声**。
现在 `theory/kern.js` 和 `assets/js/site.js` 的解析器都会把无法识别的记号收集起来并告警。
**新增解析代码时请保持这个习惯。**

## 附录：第三轮（三声部）新增的发现

### 又抓到 2 个 bug

| # | 问题 | 性质 | 出处 |
|---|---|---|---|
| 5 | **kern 谱号的八度移位被忽略**。`*clefGv2` 是声乐次中音谱号，**实际发音比记谱低八度**。忽略它导致三声部谱例的低音声部整体读高一个八度，进而把 Fux 的正常写法误判成声部交错 | 解析器 bug | Fux 图 154 |
| 6 | **`pairsCheck` 把低音写死成"最后一个声部"**。kern 语料里低音恰恰是**第一列**，所以判定蒙对了也蒙错了 | 逻辑 bug | Fux 图 101 |

### 撤回一条规则

原先打算实现的 `H12「上方声部之间的纯四度」` **已放弃自动判定**。

常见说法是"三声部里低音上方的四度算协和，两个上方声部之间的四度仍不协和"。
但 Fux 图 101 第 4 小节是 `F3–A3–D4`，**A3 到 D4 正是两个上方声部之间的纯四度，而 Fux 本人就是这么写的**——
因为 F3–D4 是六度、F3–A3 是三度，两个上方声部各自与低音协和，它们之间的四度只是排列的副产物。

**结论**：那句规则针对的是"只有这两个声部"的情形，不能套用到"三声部织体里任意两个上方声部"。
机械实现会产生假阳性。现在只把它作为需要人判断的点记录，不自动判。

### 新增工具

- `tools/validate-fux3.js` —— 三声部声部对检查。目前查：三对声部之间的平行五/八度、声部交错。
- `theory/counterpoint.js` 的 `CP.pairsCheck(voices, opts)` —— 供上者调用。

语料已扩到 7 个文件：图 5/33/55/73/82（二声部，覆盖五种对位）+ 图 101/154（三声部，第一类与第五类）。
当前状态：**二声部 5/5 通过，三声部 2/2 通过（1 条含 1 个交错提示）**。

### 仍然没做的事

三声部的**音型层面**（经过音 / 辅助音 / cambiata / 挂留 / 终止式）尚未实现。
要做到那一步，需要把 `check()` 从"两个声部"改造成"N 个声部"，
并且逐对地跑音型判定——但要注意：**三声部里一个不协和音只要与低音协和就够了**，
不需要与每个声部都协和。这是与二声部最本质的差别，实现时容易写错。

## 附录：第四轮（规则覆盖）—— 修的是一个方法论上的漏洞

### 起因：闸门是绿的，但大部分规则从没跑过

先做了一件统计：把 7 条 Fux 语料 + 站内 8 条谱例全部喂给检查器，
数**每条规则被触发过几次**。结果是：

```
21 条规则里，整个测试面上只有 5 条曾经触发过
（H01、H02、E02、E03、H08 出自站内反例；H05、H07、H10、H11、M02 出自 Fux 语料）
```

也就是说，**"Fux 的解答被判违规 0 条"这个指标，只证明 8 条规则没冤枉 Fux**；
剩下 13 条根本没用上，它们的状态是"未经检验"，不是"检验通过"。

根因在 `tools/verify.js` 的判定：

```js
if (!res.ok) intentionalCaught++;     // 只要随便报一个错就算这条反例被检出
```

三条反例合计报了 9 个不同的错误编号，却没有任何断言要求
「平行五度」那条反例真的是被 `H01` 抓到的。
所以任何一条规则静默失效，只要还有别的规则在报错，闸门照样绿。

### 又抓到 3 个 bug（都是"规则从没被跑过"的直接后果）

| # | 问题 | 性质 | 证据 |
|---|---|---|---|
| 7 | **M05「超出声部音域」是死规则**。它靠 `opts['range_'+label]`（即 `range_CF` / `range_CP`）驱动，而**全仓库没有任何调用方传过 range 选项**。一个登记为 `error` 的硬规则从不生效 | 接线 bug | 构造含 C2 的声部：不传 opts → 0 条；按第 102 行 JSDoc 传 `rangeLower` → 0 条；传 `range_CP` → 1 条。同一功能三套名字（JSDoc 写 `rangeUpper`/`rangeLower`，第 367 行读的也是它们，第 371 行真正生效的是 `range_CF`/`range_CP`），写错了没有任何东西会报错 |
| 8 | **M06「跳进后未填满音域」是空规则**。登记在规则表、也写在本文档的规则一览里，但**没有任何 `add('M06')` 调用** | 未实现 | 已补实现（见下） |
| 9 | **H08 在第一类里用 `class === 'dissonant'` 判「不协和」**，而 `core.js` 的 `intervalBetween` 只把 `simpleNum` 为 3/6 的大小音程算作 `imperfect`，**复音程一律落到 `dissonant`** | 判据 bug | 纯十二度、大十度这些完全正常的写法被判成不协和；而真正的不协和（小七度）因为同属 `dissonant` 反而蒙对了。现在按「归约后的简单音程」判定：1/5/8 须为纯，3/6 须为大或小 |

第 7、8 条的共同点：**规则挂着编号和判据说明，看起来像"有"，
实际上从没执行过**。这与第六节「静默失败是最糟的失败」是同一条教训，
只是这次失效的不是解析器，而是规则本身。
